## 八、核心业务功能梳理

### 8.1 登录流程

```
启动窗口创建完毕
  → 读取 config.ini 中缓存的账号密码
  → 点击登录 → POST http://120.26.177.153/login
    → 解析返回 token
    → 若成功 → 打开主体窗口
    → 若失败 → 弹窗提示
```

> [!CAUTION]
> 登录接口使用明文 **HTTP**（`http://120.26.177.153/login`），账号密码在网络传输中**不加密**，存在安全风险。

### 8.2 多账号多线程并发架构

程序支持多个 JD 子账号同时并行操作，设计模式为：

```
主控线程
  └── 按文件分片，轮询账号池获取可用账号索引
       └── 线程_启动多参_文本型(账号ID, 文件路径, 操作类型, ...)
            └── 处理XXX导入(账号ID, 文件, ...)
                 └── 用该账号 Cookie 提交 HTTP 请求
```

涉及以下多线程业务：
- `多账号多线程新增店铺商品导入`
- `多账号多线程物流属性导入`
- `多账号多线程采购入库导入`
- `多账号多线程退供导入`
- `多账号多线程简称导入`

## 九、安全与代码质量诊断

> [!CAUTION]
> **硬编码 HTTP 明文接口**
> - `http://120.26.177.153/login` — 登录接口
> - `http://120.26.177.153/getInfo` — 用户信息接口
> 
> 建议改为 HTTPS，并对账号密码进行加密传输。

> [!WARNING]
> **进程 DEP 保护被主动关闭**
> - 启动时调用 `SetProcessDEPPolicy(0)` 禁用 DEP，降低进程安全性。

> [!WARNING]
> **大量注释掉的死代码**
> - 代码中存在大量被单引号注释掉的逻辑（旧实现痕迹），增加了维护难度。

> [!NOTE]
> **config.ini 明文存储密码**
> - 账号密码以明文写入 `config.ini`，有本地泄露风险，建议加密存储。

> [!TIP]
> **多线程设计合理，但缺少异常处理兜底**
> - 线程启动后缺少统一的异常捕获机制，若子线程崩溃不会通知主线程，难以调试。

## 十、总结

`京东打标助手-1.0.e` 是一个面向京东云物流 (WMS) 的**批量自动化操作工具**，核心功能是：

1. **账号管理** — 支持多个 JD 子账号 Cookie 管理
2. **批量导入** — 商品、物流属性、采购入库、退供、简称、换标
3. **自动化打标** — 按时间段自动执行商品打标
4. **EdgeView 浏览器集成** — 内嵌 Edge 浏览器用于 JD 平台登录

架构上采用**多账号 + 多线程轮询**模式，通过 config.ini 持久化配置，日志写入本地文件。

总体代码量较大，业务逻辑较为完整，但存在明文 HTTP 传输、DEP 关闭、密码明文存储等安全问题，建议后续版本改进。
